## Purpose

## Decisions

- Post status reuses `NewsStatus` (the contract has one item status). Public URL is `{site}/blog/{slug}`;
  media URLs are absolute, `{site}/media/yyyy/mm/<32 hex>.<ext>`.
- The author name is stored on the post when it is created (user display name or API client name).
- Tags are matched by slug (`Tag.SlugFor`); the first spelling names the tag. Responses list tags in slug order.
- Images use SkiaSharp (MIT) plus `SkiaSharp.NativeAssets.Linux.NoDependencies` for Linux and containers.
  `MediaImages` decodes into an unpremultiplied bitmap with no color space, applies the EXIF orientation by
  remapping pixels, and re-encodes (PNG, JPEG q90, WebP q90), so no metadata or ICC profile survives.
- Skia encodes no AVIF, so an AVIF is stored as it came, but refused when it has an `Exif` or `mime` (XMP) item or a top-level `uuid` box.
- Images larger than 8000 px on a side are refused. Out of scope here: `GET /api/v1/media` and `DELETE /api/v1/media/{id}`
  from the contract (the task names only POST). The cover foreign key is `Restrict` for the later DELETE.

## Tried and rejected

- ImageSharp 3.2 and later (4.1.3 was used first): Release builds fail without a Six Labors license key.
- ImageSharp 3.1.12 (no license gate): has a known high severity advisory (GHSA-j3p4-wp97-rph4), so NuGetAudit fails the build.
- Magick.NET: would re-encode AVIF too, but ImageMagick is a much larger attack surface for untrusted uploads.
