## Decisions

- Flat settings fields, like `pipelineFailureNotify`. Settings categories restrict what main
  lists; the card's filter narrows within them. "Never" notifies nothing via the threshold.
- `news.md` sits in Getting started next to `dashboard.md`.
- The e2e presses "Check for news now" instead of waiting for the 30 second first poll, and
  restarts with `closeApp(first.app, first.root)` then `launchApp({ reuseRoot })`, closing the
  apps in reverse order so the first one's cleanup does not delete the second one's profile.
- The detail endpoint is fetched twice when an item is opened (the change event after it is
  marked read reloads every news query). That is expected, so the spec only checks it was fetched.
- T024 and T025 went into one commit, as leg 2 decided, because they share files. Left out:
  `SiteAccessPanel.tsx` (another session's WordPress work) and other tasks' `docs/tasks` files.

## Tried and rejected

- Rendering NewsSettings with defaults before settings load: the controls flashed the defaults.
  A skeleton is shown instead.
- `pnpm --filter @runova/desktop test:e2e -- news`: pnpm passes the `--` on and Playwright runs
  the whole suite. Use `npx playwright test -c e2e/playwright.config.ts news.e2e` from
  `apps/desktop` (with `RUNOVA_E2E_SKIP_BUILD=1` after one build).
