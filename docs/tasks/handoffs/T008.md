## Decisions

- The signing key is sealed with Data Protection and the key ring lives in PostgreSQL, as the epic
  (`docs/epics/41-website-api.md` line 209) says. The contract says outside the database. The user
  was told about the conflict; do not reopen it here.
- Handler check order, path from `RawTarget`, nonce insert last; refusals are a 401 with no
  `WWW-Authenticate` and the same body for every failed check.
- Rotation sets the current key's end to now + overlap (default 1440 minutes), drops keys past
  their end and adds the new key.
- PATCH validates `expiresAt` only when it changes; no-op patches and repeat revokes save nothing
  and write no audit entry. Purge jobs are registered in `JobsSetup` like the other jobs.
