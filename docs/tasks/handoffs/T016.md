## Decisions

- The site imports the app's own `apps/desktop/src/shared/help/parse.ts` (categories, front matter,
  section anchors, link resolution), so nothing is copied.
- The filter normalizes CRLF to LF. Rules that no longer change a real article fail a unit test,
  not the build.
- `<placeholder>` text outside code is escaped to `&lt;` before rendering (the app shows it as text).
- Heading ids are overwritten in order with the app's section ids, so `x.md#anchor` links agree.
- Feature link: per-article override (relay, workspace-git, workspace-files-editor,
  workspace-browser-tests), else the route's path in a table. Articles without a route get none.
  A test checks the chosen feature lists the article in its `help` when any feature does.
- Screenshot: a Dark shot named after the article, else exact route, same path, then a path under it.
- Meta description: summary if 70 to 160 chars, else whole sentences that fit, else a word cut
  with an ellipsis; short ones get a closing sentence. All 55 are unique and in range.
- Keywords are indexed by Pagefind through `<div hidden data-pagefind-index-attrs="data-keywords">`
  inside `data-pagefind-body`. Not yet proven by a search test (see Next step).
- Python on this machine writes CRLF in text mode; use the Edit tool or `newline=''`.
