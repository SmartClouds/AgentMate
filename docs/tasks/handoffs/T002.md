## Decisions

- **No Verify.** Verify 33+ fails the build without a SponsorCheck license or claimed exemption.
  The user chose a small in-house helper (`Infrastructure/Snapshot.cs`): a mismatch writes
  `name.received.json`; rename it to `.verified.json` to accept. E41 still lists
  `Verify.XunitV3` and says "Verify snapshot"; the user should update E41 (sessions do not edit
  specs).
- **405 type is `about:blank`** (RFC 9457 default): the contract has no 405 row. Suggest adding
  `method-not-allowed | 405` to the contract table; `ProblemTypes` and its test then follow.
- Statuses without a contract type get `about:blank`. RFC 9110 links that `TypedResults.Problem`
  fills in are treated as no type and replaced by the contract's.
- Readiness runs `SELECT 1`, because a pooled connection to a stopped server opens without
  touching the network (seen in the test log).
- The connection string is read when the DbContext is built, so `WebApplicationFactory`'s
  `UseSetting` reaches it. Integration tests run as Production unless they pass an environment.
- `Program` needed no `public partial class`; .NET 10 makes it public.
- Private static fields are `_camelCase` (the editorconfig rule; `dotnet format` enforces it).

## Tried and rejected

- Claiming a Verify exemption: a claim about revenue that only the user can make.
- Adding a 405 row to the contract here: RELAY says a session never edits its specs.
