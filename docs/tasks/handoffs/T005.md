## Decisions

- `Sentry.OpenTelemetry.Exporter` with `options.UseOtlp()`: events take the trace id from
  `Activity.Current`; traces go only to the OTLP endpoint. `Sentry.OpenTelemetry` is obsolete.
- `options.Dsn ??= ""` in `UseSentry`: Sentry throws on a null DSN, an empty one turns it off.
  The DSN comes from `Sentry__Dsn` (the spec's name), not `SENTRY_DSN`.
- `DropSqlText` processor removes `db.statement` and `db.query.text` ahead of every exporter.
- Scrubbed headers: Cookie, Set-Cookie, Authorization, Proxy-Authorization, X-XSRF-TOKEN and
  `X-Runova-*`, from request, response context and breadcrumb data.
- Hangfire storage starts degraded when the database is down; `RegisterRecurringJobs` logs and
  goes on. The cleanup job deletes only `Purpose == invitation && ExpiresAt <= now`.
- `WebsiteApiFactory` removes `BackgroundJobServerHostedService`: a Hangfire server per test host
  ran PostgreSQL out of connections ("53300 too many clients"), and no test needs it.
- Sentry and telemetry tests run in a non-parallel collection (process-wide hub, shared listeners).

## Tried and rejected

- `Sentry.OpenTelemetry` (`UseOpenTelemetry` plus `AddSentry`): obsolete in 6.12, breaks the build.
- Hand-written retry loops for the Hangfire schema: Hangfire.PostgreSql 1.21 has them built in.
- `new Breadcrumb(timestamp, ...)`: that constructor is not public.
- Leaving the Hangfire server on in tests: exhausts database connections.
