## Decisions

- Lockout: the 5th wrong password locks and still answers 401; every attempt after that answers
  423 `account-locked` with `retryAfter`, the right password too.
- A wrong or reused two-factor code answers 401 `two-factor-required` and counts as a failure.
- One-use TOTP through a custom token provider registered under Identity's authenticator name,
  storing `AppUser.LastTotpTimeStep`. Time comes from the injected `TimeProvider`.
- Antiforgery is our own middleware between authentication and authorization (the built-in one
  only checks forms). The token is reissued after sign-in because it is bound to the user.
- The fallback policy applies only to `RouteEndpoint`s (`RouteOnlyAuthorizationResultHandler`),
  so unknown paths still answer 404 and wrong methods 405 instead of 401.
- POST users/me/two-factor while 2FA is already on answers 409 `conflict`; the contract lists only
  200 and 401 there. The user should add 409 to the contract.
- Migrate-on-start is an `IHostedLifecycleService`, since code after `builder.Build()` never runs
  under `WebApplicationFactory`.
