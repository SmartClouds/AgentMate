## Decisions

- One live setup link per user: issuing any link (invite, re-invite, reset) deletes the user's
  others; using a link deletes it. Token hash is SHA-256 of the token's ASCII text. Site origin
  from `Website:SiteUrl`, default `https://runovahq.com`.
- "Accepted" means the user has a password hash (re-invite then answers 409).
- Last Admin = no other enabled Admin, checked in a transaction after
  `pg_advisory_xact_lock(41004)`. Disabled Admins do not count.
- Disable and two-factor reset change the security stamp, so sessions end within the 5-minute
  validation interval.
- Audit entries are saved in the request's transaction; a no-op patch or a refused change writes
  none. Setting a password from a link writes `user.update` with the user as actor. Changes JSON
  never holds a token or password.
- GET `/api/v1/audit-entries` is not built: T004's scope names only the entity.
- Date-time OpenAPI types are fixed with a schema transformer rather than by dropping the custom
  time converter, so the millisecond UTC format stays.
