## Purpose

The desktop main process keeps an offline-safe list of runovahq.com news, works out which items
affect tools installed on this machine, and notifies once about a matched high or critical
security item. No UI (that is T024).

## Decisions

- Read, dismissed and notified ids live in `settings.json` as `newsState`, written only through
  `store.updateSettings`. The cache file is not backed up.
- `news:list` leaves dismissed items out (so paging is right); `news:get` still returns them with
  `dismissed: true`. `stale` is in memory: false until this run's first poll fails.
- The notifier picks the due items again inside `updateState`, so an item read between the check
  and the write stays quiet, and it marks before it shows anything (a failed save shows nothing).
- Notification route is `/?news=<slug>`; T024 must open the detail sheet from that query.
- `minSeverity` for notifications defaults to `high`; the setting and "news off" are T025.

## Tried and rejected

- A whole-page zod reject on any bad item: one new enum value on the server would blank the card.
- Building the Dev Setup service just to peek: `peekDevSetup` returns `{}` until it exists.
